Запитання
1. Чому не можна просто виконати ALTER TABLE ... ADD CONSTRAINT CHECK (...) у SQLite?

SQLite має обмежені можливості зміни структури вже створеної таблиці. Команда ALTER TABLE не підтримує довільне додавання нового обмеження CHECK через ADD CONSTRAINT. Зазвичай потрібно створити нову таблицю з потрібним обмеженням, перенести дані, а потім замінити стару таблицю новою.

2. Що станеться, якщо додати NOT NULL до стовпця, де вже є NULL?

Перенесення завершиться помилкою. Перед зміною потрібно знайти такі рядки й визначити, чи можна коректно заповнити відсутні значення.

3. Чим CHECK після перестворення відрізняється від CHECK під час CREATE TABLE?

Різниця полягає в способі створення: у першому випадку таблицю доводиться перестворювати, а в другому обмеження задається одразу під час її створення.

4. Чому DEFAULT не перевіряють спробою порушення?

DEFAULT не забороняє значення, а підставляє його автоматично, якщо під час вставлення стовпець пропущено. Тому його перевіряють успішним INSERT, у якому відповідний стовпець не вказано, а потім за допомогою SELECT перевіряють, яке значення було підставлено.
