Запитання

1. Чим UPDATE ... SET колонка = колонка + 1 відрізняється від UPDATE ... SET колонка = конкретне число?

У першому випадку значення змінюється відносно поточного: наприклад, quantity = quantity + 1 збільшує кількість на одиницю. У другому випадку стовпець отримує конкретне значення незалежно від попереднього, наприклад quantity = 5.

2. Чому NOT NULL, UNIQUE і CHECK перевіряються при UPDATE, а FOREIGN KEY залежить від PRAGMA foreign_keys?

Обмеження NOT NULL, UNIQUE і CHECK перевіряються SQLite під час зміни рядків відповідно до правил таблиці. Перевірка зовнішніх ключів у SQLite за замовчуванням може бути вимкнена для конкретного з'єднання, тому потрібно виконати PRAGMA foreign_keys = ON;, щоб SQLite контролювала посилальну цілісність.

3. Що змінилося б, якби замість RESTRICT використовувався CASCADE?

З ON DELETE CASCADE видалення книги автоматично видалило б усі пов'язані з нею записи в loans. З ON DELETE RESTRICT видалення книги за наявності таких записів забороняється, що допомагає зберігати історію видач.

4. Чому DELETE без WHERE небезпечніший за помилку типу чи порушення обмеження цілісності?

Команда DELETE без WHERE видаляє всі рядки таблиці, а не один конкретний запис. Така операція може успішно виконатися без помилки й призвести до втрати великої кількості даних, тоді як помилки типів або обмежень зазвичай зупиняють конкретну операцію та повідомляють про порушення.
